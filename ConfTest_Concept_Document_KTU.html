1. Executive Summary & Problem Disproof

Formal Research Verdict on Original Broad Proposal:
“REJECT THIS PROJECT AS CURRENTLY DEFINED (AI-Based Repository-Aware Regression Testing and Code Change Risk Detection).”
Rationale: Meta (Machalica et al., ICSE-SEIP 2019) and Google (Memon et al., 2017) have already solved standard ML test selection using GBDT and static dependency analysis. Standard ML test selectors suffer from uncontrolled false negatives due to miscalibrated confidence scores on out-of-distribution code changes.

The ConfTest Solution: ConfTest reframes regression test selection around Risk-Calibrated Selective Prediction. By coupling high-throughput LightGBM classifiers with Venn-Abers / Conformal Calibration, ConfTest explicitly quantifies prediction uncertainty. When uncertainty exceeds a safety budget τ, the decision engine ABSTAINS and executes the safe full suite. The target set for this mechanism was 40–50% test time reduction while bounding missed regressions. Measured: the bound held (zero escaped commits on 183 held-out commits) and the reduction target did not (3.11% of executions, 0.0% wall-clock, at 97.81% abstention).

3. 25-Gap Analysis & Research Classification

We systematically analyzed 25 potential research avenues. The top open gaps driving ConfTest include:

  • Strong Gap Uncertainty-Aware Regression Test Selection: Providing calibrated confidence bounds for test execution.
  • Strong Gap Selective Prediction & Abstention Policy: Automatic fallback to full test runs when diff uncertainty is high.
  • Strong Gap Expected Calibration Error (ECE) Minimization in CI: Aligning model confidence with true empirical fault probability.
  • Strong Gap Cross-Repository Cold Start Generalization: Safely handling unseen repositories via default abstention.
  • Partially Solved Explainable Test Selection: Using TreeSHAP to display why tests were selected in PR comments.
  • Already Solved Flakiness Detection: Saturated by DeFlaker; used strictly as a data-cleaning filter.

5. Mathematical Formulation & Key Metrics

Test Reduction Ratio (TRR):   $$TRR = \left( 1 - \frac{|\mathcal{T}_{\text{selected}}|}{|\mathcal{T}_{\text{total}}|} \right) \times 100\%$$
Execution Time Reduction (ETR):   $$ETR = \left( 1 - \frac{\sum_{T_i \in \mathcal{T}_{\text{selected}}} \text{Duration}(T_i)}{\sum_{T_i \in \mathcal{T}_{\text{total}}} \text{Duration}(T_i)} \right) \times 100\%$$
Expected Calibration Error (ECE):   $$ECE = \sum_{k=1}^{K} \frac{|B_k|}{N} \Big| \text{acc}(B_k) - \text{conf}(B_k) \Big|$$
Selective Decision Policy:   $$\text{Decision}(\Delta C) = \begin{cases} \text{ABSTAIN (Run Full Suite)}, & \text{if } \max_{i} U(X_i) > \tau_{\text{abstain}} \\ \text{SELECTIVE RUN } \{T_i \mid P_{\text{cal}}(T_i) \ge \theta_{\text{select}}\}, & \text{otherwise} \end{cases}$$

8. Viva Voce Defense Guide (Top Questions)

1. Why use ML when deterministic tools like Ekstazi exist?
“Ekstazi relies on bytecode checksums. When a widely used utility class or base interface is modified, Ekstazi selects 90–100% of the entire test suite, eliminating any time savings. ConfTest learns fine-grained empirical failure patterns, allowing safe sub-selection even when high-level modules are touched.”

2. What is 'Miscalibration' and why is it dangerous in software testing?
“Miscalibration means predicted probabilities do not match empirical reality. An uncalibrated model might predict 90% confidence that a test is irrelevant, yet on unfamiliar refactoring commits, it is wrong 40% of the time, letting bugs escape into production. ConfTest uses Temperature Scaling and Venn-Abers calibration to minimize ECE.”

3. How does ConfTest prevent Data Leakage?
“We enforce strict Temporal Splitting: historical commits are sorted chronologically—the first 70% are used for training, the next 15% for post-hoc calibration, and the final 15% strictly for unseen test evaluation. Random k-fold cross-validation across commits is strictly forbidden.”
