ConfTest: Confidence-Calibrated Regression Test Selection with Selective Prediction for Continuous Integration Optimization
Final-Year Research Team, Department of Computer Science & Engineering
APJ Abdul Kalam Technological University (KTU), Kerala, India

Abstract—Continuous Integration (CI) test suites in modern agile development have expanded dramatically, often requiring over an hour per pull request. While machine-learning-based Predictive Test Selection (PTS) has emerged to prune redundant executions, existing ML selectors suffer from a critical limitation: severe miscalibration on out-of-distribution (OOD) code changes, leading to uncontrolled false-negative rates and broken builds escaping into production. In this paper, we propose ConfTest, a novel regression test selection framework based on Confidence-Calibrated Selective Prediction. ConfTest combines structural AST diff metrics, static call-graph dependencies, and historical execution dynamics with an ultra-fast LightGBM scoring engine. It applies post-hoc Temperature Scaling and Venn-Abers calibration to explicitly quantify prediction uncertainty. When uncertainty exceeds a safety budget τ, the system safely abstains to full-suite execution. We evaluate on 1,213 commits and 561,711 (commit, test) pairs mined from five open-source Python repositories, with every label obtained by executing the suite against a generated mutant and with chronological splits cut on mutant boundaries. Our findings are mixed and we report them as such. Temperature scaling reduces Expected Calibration Error from 0.0390 to 0.0242 ($T^* = 0.7941$; paired improvement 0.0148, 95% CI [0.0030, 0.0393] bootstrapped by mutant). On 183 held-out commits (86,469 pairs) the shipped operating point attains 100.0% failure recall with zero escaped commits, but abstains on 97.81% of commits and therefore reduces test executions by only 3.11%, with a 0.0% wall-clock reduction. Tightening the abstention threshold to reach a 32.85% reduction drops held-out recall to 87.69% with 15 escaped commits, failing our pre-registered 95% recall floor by an 8.33 percentage-point validation-to-test generalization gap. We conclude that the selective-prediction mechanism is sound and reusable while the underlying ranker (PR-AUC 0.1393 against a 3.71% positive rate) is not yet accurate enough to convert abstention into a useful saving — a negative result we believe is more useful to the RTS community than the alternative of tuning on the test split.

Index Terms—Regression Test Selection, Continuous Integration, Confidence Calibration, Selective Prediction, Expected Calibration Error, Machine Learning in SE.

I. Introduction

Continuous Integration (CI) and Continuous Delivery (CD) are cornerstones of modern software engineering. However, the sheer size of regression test suites creates severe feedback latency. In large repositories, executing all tests on every pull request is economically and operationally prohibitive [1].

Prior industrial systems, such as Meta's Predictive Test Selection [2], pioneered Gradient Boosted Decision Trees (GBDT) to predict test failures. However, standard classifiers output uncalibrated pseudo-probabilities. When developers push large refactorings or external dependency modifications, these models fail silently, dropping breaking tests. In real-world software engineering, a single escaped defect can cost thousands of dollars, negating all cloud runner savings.

To resolve this fundamental tension between test execution speed and developer safety, we present ConfTest. ConfTest introduces Selective Prediction with Calibrated Abstention to continuous integration.

II. Proposed Method

A. Feature Taxonomy

For every test case $T_i$ given commit diff $\Delta C$, ConfTest extracts a 32-dimensional vector spanning four domains: (1) Syntactic AST churn (LOC delta, AST node edits, interface changes via Tree-sitter); (2) Static dependency overlap (call graph distance and import matching); (3) Historical dynamics (time-decayed failure frequency and average duration); and (4) diff churn magnitude. One caveat belongs up front: 13 of the 32 columns are constant across our training split, and all 12 diff-churn columns are among them, which indicates a defect in diff mining rather than a property of churn. No conclusion about churn should be drawn from our results.

B. Probability Calibration & Uncertainty Quantification

Raw margin outputs $s_i$ from LightGBM are calibrated using post-hoc Temperature Scaling:

$$P_{\text{cal}}(Fail | X_i) = \sigma(s_i / T) = \frac{1}{1 + e^{-s_i / T}}$$

where $T > 0$ is optimized on a held-out temporal calibration set by minimizing Negative Log-Likelihood (NLL). A bounded scalar minimiser over $\log T$ converges in 17 iterations to $T^* = 0.7941$ (validation NLL $0.19290 \rightarrow 0.18345$). $T^* < 1$ means our ensemble is under-confident on this split, the opposite of the overconfidence usually reported for deep networks. We also fitted isotonic regression and rejected it: it reaches a lower mean ECE (0.0166) but raises worst-bin error from 0.1235 to 0.2098 (paired degradation $+0.0863$, 95% CI [0.0299, 0.1135]), and an abstention gate is thresholded on the tail of the confidence distribution, so a method that is better on average and much worse in its worst bin is the wrong trade. Epistemic uncertainty $U(X_i)$ is computed across calibrated ensemble margins.

C. Selective Prediction & Abstention Policy

ConfTest implements a formal decision rule:

$$\text{Decision}(\Delta C) = \begin{cases} \text{ABSTAIN (Full Suite)}, & \text{if } \max_i U(X_i) > \tau_{\text{abstain}} \\ \text{SELECTIVE RUN}, & \text{otherwise} \end{cases}$$

This ensures that during high-uncertainty or out-of-distribution code changes, the system automatically defaults to a 100% safe full test run.

III. Experimental Evaluation

We evaluate ConfTest against 7 baselines using chronological temporal splitting cut on mutant boundaries, so that no mutant contributes rows to more than one split: 849 commits / 391,825 rows for training (5.017% positive), 181 / 83,417 for validation (5.488%), and 183 / 86,469 held out (3.710%). A. The 95% Recall Floor Is Not Met at a Useful Reduction

We pre-registered a 95% held-out failure-recall floor. Selecting $\tau_{\text{abstain}} = 0.044$ on validation gives 32.85% test reduction at 96.02% recall; carrying the same threshold to the held-out split gives 32.85% reduction (95% CI [26.50, 39.18]) at 87.69% recall ([75.77, 95.81]), with 15 escaped commits and 395 missed failures. The floor is missed at the point estimate and at the CI lower bound, and the validation-to-test recall gap is 8.33 percentage points (reports/g5_recall_floor.json records gate_met: false). A post-hoc sweep of the held-out split does contain five thresholds that would clear 95% (best: 26.56% reduction at 97.35% recall), but selecting a threshold by its test-set score would mean the number is no longer held out, so we record that sweep as a diagnostic and deliberately do not use it.

IV. Statistical Significance

Confidence intervals are bootstrap intervals over 2,000 resamples with the commit as the resampling unit, because the 86,469 rows are not independent (reports/statistical_significance.json). Failure recall is [100.0%, 100.0%] over the $n = 135$ commits that had at least one failure. Wall-clock time reduction has mean 1.05%, 95% CI [0.25%, 2.10%] over $n = 183$ commits, with a median of $-0.0\%$: the typical commit saves nothing. Cliff $\delta$ on failure recall runs 0.5111 to 0.9852 against the subset baselines, and exactly 0.0 against Retest-All ($p = 1.0$, identical by construction). Cliff $\delta$ on time reduction runs $-0.906$ to $-0.998$, i.e. negative against every subset baseline: ConfTest is significantly worse on savings than every strategy it beats on recall, and reporting only the recall effect sizes would be cherry-picking.

A. Threats to Validity

Cross-project transfer. Leave-one-project-out over the five repositories gives a macro-average recall of 51.57% at a 25% budget (30.00% to 88.42%), macro ROC-AUC 0.7004, and held-out ECE 0.2957 against 0.0242 in-distribution. On one project ROC-AUC is 0.4747, below chance. Zero-shot transfer to an unseen repository does not work, and the abstention gate cannot be trusted there.

Stale artifacts. The committed ensemble was trained with the LightGBM subsample parameter set but subsample_freq left at its default of 0, which silently disables row bagging; the five seeds therefore differed only in column sampling and tie-breaking, so the reported epistemic $\sigma$ underestimates true ensemble diversity. The training code is corrected but no artifact has been regenerated, and $\sigma$ is precisely the quantity the abstention gate thresholds.

Latency scope. Our 3.345 ms mean scoring latency (P99 4.435 ms) covers array sanitisation, ensemble inference, calibration and the policy decision only. It excludes feature mining, which dominates real per-commit cost, and a 1321.8 ms cold start on the first batch in a fresh process.

V. Conclusion

We set out to reduce CI test time without missing regressions, and we achieved one of those two things. The selective policy escaped zero regressions across 183 held-out commits because it declines to select whenever ensemble disagreement or distributional novelty exceeds a tuned threshold; that safety property is real and measured. It also abstains on 97.81% of commits, reducing test executions by 3.11% and wall-clock time by 0.0%, so the economic case is not made. The binding constraint is the accuracy of the underlying ranker, not the selective-prediction machinery built around it, and the abstention gate remains a reusable component for any future RTS ranker strong enough to exploit it.
